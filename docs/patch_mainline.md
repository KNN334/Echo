# 贴片项目主线

本项目的主线已经按手写笔记重排为：

```text
贴片采集
  -> RF/IQ 记录与事件对齐
  -> 波束合成与 B-mode 成像
  -> 逐帧左心室分割（FCN-32 作为论文对齐基线）
  -> 物理坐标下的面积、长轴和直径
  -> EDV/ESV
  -> SV、EF、HR、CO
  -> 独立参考和分层验证
```

论文正文和补充材料只作为方法来源，不作为本项目已经完成的贴片实验结果。当前仓库的 CAMUS 数据仍然是公开图像基线，承担分割、几何和时间逻辑的可复现检查；它不能证明贴片硬件、RF/IQ 波束合成或佩戴状态下的连续监测已经完成。

## 数据分支

`configs/experiment.yaml` 保留 CAMUS / EchoNet 基线。`configs/experiment_patch.yaml` 是新的贴片主线配置，使用 `patch` 适配器和 FCN-32 风格模型。该配置需要真实的 `data/processed/patch`、患者级划分和贴片记录后才能运行；仓库不放入虚假的患者数据或参考值。

贴片记录遵循 `docs/templates/patch_record.template.yaml`。输入层级必须明确是通道 RF、通道 IQ、已波束合成信号、包络还是 B-mode。若仍在通道层，必须记录阵元坐标、通道映射、发射事件、采样率和时间参考，才能进入可复现的延时求和。若已经是 B-mode，只能核查图像几何、方向、时间戳和处理溯源，不能把设备播放帧率自动当作采集帧率。

`src/patch/contract.py` 会把证据缺口转成显式状态：

- 没有空间标定时，绝对容积保持 `null`，不把像素立方体积写成 mL；
- 没有经过验证的采集时间或完整周期时，HR 和 CO 保持 `null`；
- 没有独立 CO 参考时，不能把同一几何方法的结果称为独立临床验证；
- 审阅状态只能来自记录，不能由预处理自动改成 `reviewed`。

## 成像和模型

`src/patch/beamforming.py` 只提供可审计的数值积木：角度表、延时求和、包络、对数压缩和 RMS。它不会猜测设备的阵元排列、声速、发射序列或相位约定。真实设备接入时，应先用点靶或仿体验证延迟和空间坐标，再接入心脏序列。

论文使用宽波束复合和 3 MHz、32 阵元、0.4 mm pitch 等装置参数。手写笔记中的具体参数只作为待核对的设备记录，不能直接写进实际数据的元数据。当前模型分支提供 `fcn32`，用于与论文的模型选择逻辑对齐；它的验证指标必须在贴片患者级划分上重新测量。

## 功能量化

逐帧分割后，使用物理坐标计算面积、长轴和直径，再按 ED/ES 计算：

\[
SV = EDV - ESV, \qquad EF = 100 \times SV / EDV,
\]

\[
HR_k = 60/(t_{ED,k+1}-t_{ED,k}), \qquad CO_k = SV_k HR_k/1000.
\]

半周期数据不反射、不拼接成完整周期。短暂遮挡和无效区间只在连续有效段内分析，输出中保留覆盖率、缺口和失败原因。

## 验证层级

验证分为四层：图像/波束质量、分割质量、同几何几何量化、独立功能参考。CAMUS 的专家 ED/ES 轮廓可以验证分割和同几何误差，但不能替代贴片采集验证，也不能替代独立 CO。四视图、姿态和运动状态必须分别记录，A4C 在运动状态下是否可用不能由论文中的静态示例推断。

运行 `python scripts/check_patch_contract.py <record.yaml>` 可以先检查记录是否允许计算绝对容积、HR 和 CO。通过契约检查不等于实验完成；完整原始数据、完整预处理、完整模型实验和本地缓存覆盖率仍分别报告。
