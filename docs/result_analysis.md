# 结果分析图：设计、复现和证据边界

本次图件分析固定使用 `runs/camus_cuda_progress` 的已完成测试输出及匹配的 `checkpoints/camus_cuda_progress` 训练记录。选用依据是已完成实验及权重摘要一致性，不根据测试分数选模型。历史 `reports/full_baseline` 是另一轮实验，不混合两轮指标，也不重新训练或改变测试阈值。

## 绘图前的证据设计

| 图件 | 要回答的问题 | 证据角色与限制 |
|---|---|---|
| 01 训练曲线 | 验证损失何时最低，之后是否出现泛化差距？ | 训练与验证 BCE；最佳轮次只由验证集决定；没有测试损失曲线 |
| 02 分割分布 | 两个切面、两个相位的误差分布怎样？ | Dice、ASSD、HD95 三类互补指标；保留全部有效点，组内每点一患者 |
| 03 容积一致性 | 分割误差向 EDV/ESV 传递多大？ | 双平面预测与专家轮廓经同法计算的参考；散点与患者级 Bland–Altman |
| 04 功能一致性 | 同法参考下 SV/EF 的误差怎样？ | 误差传播到下游指标；不当作独立临床验证 |
| 05 数据集 EF | 与 CAMUS 报告 EF 的一致性怎样？ | 与同法轮廓参考分开；独立的图和标题，不混用参考层级 |
| 06 自动选相位 | 自动选帧在共同可评价患者上改变了多少误差？ | 配对比较，报告缺失数；不能把半周期极值称为完整心搏识别 |
| 07 覆盖率 | 哪些结论实际有数据支持？ | 有效患者数/全部尝试患者；人工关键点、独立 CO 缺失不画成零误差 |
| 08 定性叠图 | 典型与差例中轮廓错在哪里？ | 以测试病例平均 Dice 的最差、25%、50%、75% 排名确定示例；非随机代表样本 |
| 09 半周期 | 中间帧预测与端点参考的关系如何？ | 保留真实时间顺序；只画两个专家端点，不补造中间真值或完整周期 |
| 10 误差关联 | 图像质量和分割分数是否足以解释 EF 误差？ | 患者级探索性分层与关联；不作因果或临床等效性结论 |

采用项目既有 Python 工作流，白底、统一蓝/橙配色，导出可编辑 SVG、PDF 和 300 dpi PNG；宽度 183 mm，正文至少 7 pt。每图保留图注、源数据与统计口径；进行绘图后面板对齐、PDF 文字和碰撞检查，再检查实际预览。

## 参考图是否符合本项目

提供的参考图对应 Hu 等发表于 Nature（2023）的 *A wearable cardiac ultrasound imager* Fig. 5，DOI `10.1038/s41586-022-05498-z`。整体思想是左室分割、几何容积和心功能计算，但不能当作本项目的逐项实现图。

1. 该研究使用 FCN-32；本项目使用 EchoNet 风格 DeepLabV3-ResNet50，不能照搬网络模块。
2. 该图展示 PCA、旋转与切片积分；本项目的 PCA 用于轮廓候选关键点，单平面为面积–长度近似，双平面为 20 椭圆盘。不能将两套容积算法视为完全相同。
3. 该图有完整重复周期、数分钟连续采集及设备对照。本项目 CAMUS 半周期不能支撑对应的长时间容积、心率、CO 或运动恢复曲线。
4. 本项目 2CH/4CH 为先后采集，仅同患者 ED/ES 相位配对，不构建同步逐帧双平面曲线。
5. 当前训练仅使用专家 ED/ES 帧。对中间帧推理本身不会将本项目变成半监督训练。

## 复现

在项目根目录运行：

```powershell
python -m pip install -e ".[visualization]"
python scripts/plot_results.py --results runs/camus_cuda_progress --training checkpoints/camus_cuda_progress --prepared data/processed/camus --output reports/result_analysis/camus_cuda_progress
```

入口仅分析已保存结果，不运行模型或接触原始下载流程。核心定量图不需要模型依赖；定性叠图和半周期示例需要匹配的处理后病例缓存。输出为总览网页、中文解读、全部图片及 CSV/JSON 源数据。更换实验时必须同时指定匹配的结果和训练目录，不能混用权重。

完整原始数据下载、完整预处理、完整模型实验、本地缓存是不同核查项；本次只核查绘图涉及的缓存及既有实验记录，不重新声称原始 Release 数据已经下载或核验。
